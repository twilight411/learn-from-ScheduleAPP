# 生图缓存机制与面试要点

## 两套接口，两套缓存

| 业务 | 接口 | 缓存表 | 指纹依据 |
|------|------|--------|----------|
| 生命树 AI 图 | `GET /tree/weekly/image` | `weekly_tree_images` | 五维分 + 树态 + 季节 |
| 月度果实 AI 图 | `GET /fruits/image` | `monthly_fruit_images` | 月分 + 果实类型 + 五维月均 |
| 植物状态（非生图） | `GET /tree/weekly` | 得分表 + `weekly_tree_enrichments` | 无图片 URL |

**植物状态不生图**；慢在 LLM 时用 **fast**（主题 03），不是给 `/tree/weekly` 加图片缓存。

---

## 命中条件（生命树示例）

```text
row 存在
AND score_fingerprint == 当前指纹
AND image_url 有效（非 neeko 占位）
AND image_status == ready
→ cached=true，~100ms，日志 tree_image_cache_hit
```

否则：调即梦 **~10s**，写库，`cached=false`。

## 常见误解澄清

| 说法 | 对错 |
|------|------|
| 「生图接口没缓存」 | ❌ 早有 `weekly_tree_images`；果实后来补上 |
| 「缓存导致 500」 | ❌ 500 是 refresh 写库 bug |
| 「二次 11ms 是内存缓存」 | ❌ 是 **DB 持久化** + 指纹命中 |
| 「refresh 也要快」 | ❌ 故意同步即梦，**~10s 正常** |

## 面试题集锦

1. **如何验证缓存生效？**  
   看响应 `cached`、日志 `cache_hit`、第二次请求延迟降两个数量级、DB 有行且 fingerprint 匹配。

2. **指纹为什么要包含分数？**  
   用户本周行为变 → 图应变；只按 `user_id+week` 会展示过时图。

3. **占位 URL 为何不缓存？**  
   否则永远命中无效图，无法触发重新生图。

4. **单进程 uvicorn 下并发？**  
   同步等外部 API 会排队；解决：异步生图、多 worker、或队列。

5. **压测为什么要 loopback？**  
   外网 143ms vs 本机 12ms → 证明服务端逻辑快，外网多 RTT；外网 10s vs 本机 10s → 证明慢在即梦而非网络。
