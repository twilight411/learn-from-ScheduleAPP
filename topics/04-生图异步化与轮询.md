# 生图异步化：`wait=false` 与状态轮询

## 遇到的问题

即使 DB 有缓存，**首次**或 **指纹变化** 仍要同步等即梦 **~10s**，阻塞植物页「加载完成」。

压测冷路径（`refresh=true`）：

- 生命树生图：**10141ms**
- 果实生图：**10032ms**

---

## 解决方法

### 接口契约

| 参数/接口 | 行为 |
|-----------|------|
| `GET .../image?wait=false` | 立即返回占位图 + `status=pending`；后台 `asyncio` 任务生图 |
| `GET .../image/status` | 轮询直到 `status=ready` + 真 `image_url` |
| `wait=true`（默认） | 保持同步，兼容旧客户端 |

### 表字段

`weekly_tree_images` / `monthly_fruit_images` 增加 `image_status`：`pending | ready | failed`。

### Flutter

`ApiPlantRepository`：`getWeeklyTreeImage(wait: false)` → 每 2s 轮询 `status`，最多约 90s。

loopback：`fruits/image` 缓存 **7ms**，`tree/weekly/image` 缓存 **12ms**。

## 面试要点

**Q：异步生图和消息队列区别？**  

A：当前用进程内 `asyncio.create_task` + 独立 DB session，适合单实例、轻量；MQ 适合多实例、可追溯、重试。面试可答：小规模用 DB `pending` 状态 + 后台任务即可，规模化再上 Celery/RQ。

**Q：占位图用户体验？**  

A：先展示骨架/默认树图，轮询成功后替换；比白屏等 10s 更好。需处理 `failed` 与超时。
