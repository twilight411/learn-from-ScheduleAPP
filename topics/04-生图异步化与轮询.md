# 生图异步化（wait=false）与状态轮询

---

## 简历写法（可直接用）

**即梦生图异步化与客户端轮询（ScheduleApp）**

- 生命树/果实生图同步阻塞 **~10s**，拖垮植物页；即梦 API 为外部长耗时，无法靠加 CPU 优化。
- 接口增加 **`wait=false`**：立即返回 **占位图或缓存 URL**，`image_status=pending`，`asyncio` 后台调即梦写库后置 `ready`。
- 新增 **`GET /tree/weekly/image/status`**、**`GET /fruits/image/status`**，Flutter **2s 轮询**直至 `ready` 或超时。
- 压测：日常 `tree/weekly/image` **10.03s → 122ms**；`fruits/image` **16.58s → 133ms**；仅 `refresh=true` 仍 **~10s**。

---

## 遇到的问题

- 即使 DB 无缓存，用户也不愿首屏白等 10s。  
- 同步 `wait=true` 时 HTTP 连接占用 worker，并发差。  
- 需要与 **已有缓存**、**refresh** 语义共存。

---

## 我做了什么

1. **协议设计**  
   - Query：`wait=false`（默认或显式）  
   - 响应：`image_url`（占位/旧图）、`image_status`、`task_id`（可选）  

2. **`background_runner.py`**  
   - 后台任务：调即梦 → UPDATE 行 `image_status=ready`  
   - 失败：`failed` + 日志，前端可重试  

3. **状态查询接口**  
   - 轻量只读，适合高频轮询（&lt;50ms 级 DB）  

4. **Flutter 适配**  
   - `ApiPlantRepository`：先展示 URL，启动 Timer 轮询 status  
   - 与 `cached=true` 组合：有旧图则零等待  

---

## 结果

| 接口 | 同步（旧） | wait=false + 缓存 |
|------|------------|-------------------|
| `tree/weekly/image` | 10.03s | **122ms** |
| `fruits/image` | 16.58s | **133ms** |
| 强制 refresh | ~10s | ~10s（后台仍异步可先做 pending） |

## 面试要点（详细）

### Q1：异步生图的标准流程画一下？

**答（口述流程）：**

1. 客户端 `GET .../image?wait=false`  
2. 服务端：有缓存 → `ready` + URL；无缓存 → `pending` + 占位/空 + 投递后台任务  
3. 客户端每 2s `GET .../image/status`  
4. `ready` → 换图；超时 → 提示重试  

与 **Sky-Chat SSE** 不同：这里是 **短轮询**，因无流式像素输出。

---

### Q2：为什么用轮询不用 WebSocket？

**答：**

- 生图 **10s 级**、状态变 **一次**，轮询 2s × 5 次足够。  
- WebSocket 要维护连接、鉴权、nginx 配置，运维成本高。  
- 简历可说：**按变更频率选协议**——高频 token 用 SSE，低频状态用 polling。

---

### Q3：占位图策略？

**答：**

- 上月/上周缓存图（**stale-while-revalidate**）  
- 静态默认 SVG/PNG  
- 模糊骨架  
- 关键：**避免 layout shift**（固定宽高盒）

---

### Q4：后台任务失败怎么办？

**答：**

- `image_status=failed`，保留上次 URL。  
- 指数退避重试（最多 3 次）。  
- 监控即梦 4xx/5xx 率；面试提 **熔断** 避免打爆配额。

---

### Q5：wait=false 时 worker 还会不会被占满？

**答：**

- 主请求很快释放；长耗时在 **后台 asyncio task**（仍占连接池到即梦）。  
- 比 **同步占住 HTTP worker 10s** 好；极端并发要 **队列 + 限流**。

---

### Q6：和「DB 缓存」关系？

**答：**

- **缓存**：避免调即梦。  
- **异步**：必须调即梦时也不阻塞首屏。  
- 两层叠加：日常 **122ms**；首次无缓存 **pending + 后台 10s**。

---

### 易错点

- 轮询间隔 100ms（浪费）；我们 **2s** 合理。  
- pending 时 `image_url` 为空导致 UI 塌缩。  
- 忘记 status 接口鉴权（越权查别人图）。
