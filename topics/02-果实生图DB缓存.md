# 月度果实生图 DB 缓存

## 遇到的问题

`GET /api/v1/fruits/image` **每次**约 **10s**，连续请求耗时不变，响应无 `cached` 字段。

压测（优化前，植物页热路径）：

- 果实接口占等待 **70–85%**
- 连续 3 次无 refresh：每次 **~10s**（无下降）

生命树 `tree/weekly/image` 已有 `weekly_tree_images` 表，命中 **&lt;100ms**；果实侧**未持久化**。

---

## 根因

`fruits.py` 每次调用 `generate_fruit_image()` → 即梦 API，**未**将 `image_url` 写入 DB，也未按得分指纹失效。

---

## 解决方法

对齐生命树模式：

| 组件 | 内容 |
|------|------|
| 表 | `monthly_fruit_images`（`user_id` + `month` + `score_fingerprint` + `image_url`） |
| 服务 | `FruitService.get_or_generate_fruit_image()` |
| 路由 | `GET /fruits/image?refresh=true` 强制重生 |
| 响应 | 增加 `cached: true \| false` |
| 策略 | 占位 URL（`neeko-copilot`）**不写入**缓存 |

---

## 数据（压测验证）

专项抽样（`month=2026-05`，账号「雅」）：

| 次序 | refresh | 耗时 | cached |
|------|---------|------|--------|
| 1 | true | **10114 ms** | false |
| 2 | false | **298 ms** | **true** |
| 3 | false | **305 ms** | **true** |

植物页热路径：**12–15s → 2–3.3s**（仍受 `tree/weekly` LLM 影响，见主题 03）。

完整报告：[api-load-benchmark-after-fruit-cache-2026-05-25.md](../benchmark-reports/api-load-benchmark-after-fruit-cache-2026-05-25.md)

## 面试要点

**Q：如何设计「生成类」接口缓存？**  

A：用**业务指纹**（得分、维度、月份）而非 URL；指纹不变则读库；`refresh` 显式失效；无效/占位结果不缓存；返回 `cached` 便于前端与监控。

**Q：缓存和 CDN 区别？**  

A：DB 缓存避免重复调**贵且慢**的生成 API；CDN 缓存静态分发。生成结果 URL 往往是第三方 CDN，我们缓存的是「指向该 URL 的映射关系」。
